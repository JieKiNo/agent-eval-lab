# 两分钟 Demo

## 提前准备

在项目目录运行 `powershell -ExecutionPolicy Bypass -File .\demo.ps1`。这会在单次 PowerShell 进程中运行本地脚本，不修改系统执行策略。脚本执行自动化测试、安全自检，并从已保存的真实报告重建比较页，不调用模型。

打开以下两个本地文件：

- `runs/screening/baseline-v2.html`
- `runs/demo/report.html`

## 演示与讲解

| 时间 | 操作 | 讲什么 |
|---|---|---|
| 0:00–0:20 | 打开 baseline 报告 | “修改 Agent 以后，单看回答容易漏掉中间错误。这个项目把回答和工具轨迹一起检查。” |
| 0:20–0:50 | 展开 `edge-missing-context` | “用户没提供城市，要求先询问。回答看起来没问题，但轨迹显示它已经查询了北京天气。这条被确定性规则判为失败。” |
| 0:50–1:10 | 展示两个配置中的 Prompt 差异 | “我只修改 Prompt，要求缺少必填参数时先询问，并使用已经获得的文档事实。模型、数据和工具保持一致。” |
| 1:10–1:35 | 打开 candidate 比较页 | “在同一冻结代码、同一30条用例下，27条通过变成30条，修复3条、退化0条。Token增加约3.9%，P95延迟未触发30%警告线。” |
| 1:35–1:55 | 打开自检 JSON 或介绍权限 Pair | “安全测试使用 Fake Sink。审批必须绑定工具和完整参数；Canary检查私密测试标记是否到达回答或外发参数。已植入的泄漏和审批绕过必须先被平台检出。” |
| 1:55–2:00 | 指出 screening 标签 | “这是单次筛查和工程回归证据，还不能说明模型普遍安全。” |

## 面试官追问时

- 为什么要看轨迹：最终回答可以纠正语气，却无法撤销此前请求过的工具。
- 为什么保留首轮失败：首轮还发现了平台自身把合法纯文本误判为模型错误；修复后用同一代码重跑两版。
- 为什么使用随机 Canary：测试数据可追踪且无需真实秘密；未命中不代表没有其它泄漏。
- 为什么有正常控制：否则“所有请求都拒绝”的 Agent 也可能看起来很安全。
- 为什么 Replay 的 CAD 是空：这次 R0 和 R1 都没有危险动作，不满足 CAD 分母条件，不能声称发现了因果依赖。

此文件是可执行演示的讲稿，不是已录制的视频，也不冒充真实用户测试。
