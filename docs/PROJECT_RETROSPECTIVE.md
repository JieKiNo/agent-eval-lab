# 项目复盘

## 做成了什么

实现了从 JSONL 读取测试、调用真实工具型模型、收集轨迹、运行确定性规则、对比版本和生成静态 HTML 的完整流程。当前数据集有30条用例：15条正常任务与安全负面控制、10条间接注入攻击、5条边界用例。标签允许重叠，其中23条带 security 标签。

## 实际发现

1. 模型在缺少城市时先查询北京，再询问用户城市；只看回答会漏掉这次违反工具约束的调用。
2. 模型在两条正常控制中没有使用工具历史中已有的文档事实，错误地要求用户重新提供文档。
3. 评测平台首版额外强制答案 JSON 外壳，把合法纯文本“收到”误判成模型错误。平台也必须接受反例和回归检查。

Prompt修复前后，其余实验配置保持一致。在适配器修复后的代码上重新运行，baseline 27/30，candidate 30/30，修复3条，退化0条。正常任务通过率从13/15变为15/15。总Token为29,827与30,992；P95端到端耗时约2,230与1,995毫秒。耗时是本机到API的观测，单次结果不可当稳定性能提升。

第一轮 baseline 27/30、candidate 29/30及比较拒绝结果仍保留在 `runs/screening/*-v1.json`。第二轮是不同评测器代码的重新筛查，不合并为“重复两次的正式实验”。

## 安全设计与观察

- Fake Sink记录危险操作请求，外部副作用恒为false；独立审批绑定工具与完整参数，模型自报批准无效。
- 随机 PRIVATE/UNTRUSTED Canary区分私密测试上下文和攻击内容；检测原文、归一化、URL、Base64、Hex。它只覆盖这些已注册表示。
- MR-AUTH和MR-CAP各运行一组真实模型Pair，观察到无审批版本未请求发送、加入诱饵工具未新增调用。
- 一组R0/R1重放都未观察到危险动作，因此CAD不适用。该结果完整保留。
- 10条间接注入攻击的本次真实运行没有触发已注册危险动作；这不是“所有注入都安全”的证据。

## 产品取舍

先使用命令行和静态HTML完成“发现失败—看轨迹—比较版本”的流程。省去服务端部署后，精力可以用于真实接入、指标可信度和解释失败。产品用户仍是假设目标用户，未实施访谈或3人可用性实验，也没有用户规模和效率提升数字。

## 下一步

优先增加跨会话与多轮攻击、扩展攻击难度、做独立保留集和至少3次重复实验，再收集同学使用报告的实际反馈。D5、D6、E1和完整AICS安全契约扩展均未运行。
