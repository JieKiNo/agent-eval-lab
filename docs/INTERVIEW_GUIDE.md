# Agent Eval Lab 用户研究指南

> 用途：为 AI 产品实习版本补充用户证据。  
> 注意：AI Agent 实习版本不要求联系 Agent 作者，也不以外部用户参与作为完成条件。

当前状态（2026-09-10）：本地产品、真实评测报告和[两分钟演示](DEMO_SCRIPT.md)已可使用。尚未联系受访者、开展访谈或记录可用性结果。本文件仍是可选研究计划。

## 1. 研究目标

不要泛泛验证“大家喜不喜欢这个产品”，只验证两个问题：

1. Agent 开发者现在怎样判断版本是否退化？
2. 用户能否根据 Agent Eval Lab 的报告找到失败原因并完成版本决策？

## 2. 参与者

找 3 名做过以下任一项目的同学即可：

- Agent；
- RAG；
- LLM 课程项目；
- 带 API 或工具调用的应用。

不要求参与者拥有公开 Agent，也不要求联系陌生开发者。

## 3. 分成两个阶段

### 阶段 A：了解现有做法

每人约 15 分钟，询问：

1. 最近一次 Agent “看起来成功、实际失败”是什么情况？
2. 修改 Prompt 或模型后，你现在怎样检查是否退化？
3. 排错时最先看什么：回答、工具、参数、上下文、耗时还是 Token？
4. 最近一次排错花了多久？
5. 你用过哪些评测或日志工具？为什么继续用或放弃？
6. 如果只能保留三项报告信息，你会保留什么？
7. 哪些工具调用属于高风险操作？现在如何限制？

尽量让参与者展示真实项目或具体记录。具体行为比假设意见更可信。

### 阶段 B：可用性任务

给参与者同一套材料，让他独立完成：

1. 根据 README 启动项目；
2. 导入给定评测集；
3. 运行 baseline；
4. 找出一个失败用例；
5. 解释失败原因；
6. 比较 baseline 与 candidate；
7. 判断是否接受 candidate。

过程中不要主动讲解。只有参与者明确卡住时才提供帮助，并记录发生位置。

## 4. 记录表

每位参与者记录：

| 字段 | 内容 |
|---|---|
| 背景 | 做过什么类型的项目 |
| 当前方法 | 现在怎样测试和排错 |
| 最近失败 | 一个具体失败案例 |
| 首次成功时间 | 从开始到跑出第一份报告 |
| 找到失败时间 | 从打开报告到指出失败原因 |
| 帮助次数 | 哪一步需要帮助 |
| 判断是否正确 | 是否正确识别 regression 和安全硬失败 |
| 最大卡点 | 最难理解的步骤或字段 |
| 用户原话 | 与行为直接相关的原话 |
| 证据强度 | 真实行为 / 具体回忆 / 假设意见 |

不要收集真实密钥、私人日志、客户数据或未脱敏项目文件。

## 5. 怎样决定改什么

优先修复同时满足以下条件的问题：

- 至少 2 人在同一步卡住；
- 阻止完成核心流程；
- 可以在当前项目范围内解决。

一次只修改一个主要问题，修改后让至少 1 人重新完成对应任务。

不要因为单个人提出一个想法，就增加新的平台功能。

## 6. 不要这样问

- “你会不会使用这个产品？”
- “这个功能是不是很好？”
- “如果免费你愿意用吗？”
- “你觉得我们要不要加某某功能？”

这些问题容易得到礼貌性肯定，不能证明真实需求。

## 7. 完成标准

- 3 人完成同一套任务；
- 每人都有时间、卡点、帮助次数和判断结果；
- 发现至少一个重复出现的问题；
- 完成一次有证据支持的修改与复测；
- 复盘中同时保留成功和失败行为。
