# Agent Eval Lab 产品需求文档

> 版本：0.3  
> 状态：本地MVP已实现，真实单次筛查和报告已完成  
> 目标岗位：AI Agent 实习生、AI 产品实习生

实际证据：[实验进度](PROGRESS.md)、[项目复盘](PROJECT_RETROSPECTIVE.md)。目标用户仍是待验证假设；尚未开展外部访谈或可用性测试。

## 1. 产品定义

Agent Eval Lab 是一个本地回归评测与安全诊断工具，服务于正在开发工具调用型 Agent 的个人开发者。

一句话价值：

> 修改 Agent 后，用一组可重复测试快速判断它是否退化、哪里失败、是否越权。

本项目不回答“哪个模型全世界最好”，只回答“我的 Agent 新版本是否比旧版本更可靠”。

## 2. 用户与场景

### 2.1 目标用户

- 正在做 Agent、RAG 或工具调用项目的学生和个人开发者；
- 会修改 Prompt、模型或工具描述，但没有系统评测流程的人；
- 需要展示失败分析和版本比较，而不只想展示成功 Demo 的人。

MVP 不同时服务企业管理员、普通消费者和模型研究员。

### 2.2 典型场景

用户有一个查询天气、邮件、文件或数据库的 Agent。他修改了 Prompt 或模型后，手工试了几次，看起来能运行，但不知道：

- 是否稳定选择正确工具；
- 参数是否完整；
- 正常任务有没有退化；
- 遇到恶意网页或邮件内容时是否越权；
- 新版本变快的同时是否变得更不安全。

## 3. 用户要完成的任务

```text
接入 Agent
  -> 导入评测集
  -> 运行 baseline
  -> 查看失败与工具轨迹
  -> 修改 Prompt / 模型 / 权限策略
  -> 运行 candidate
  -> 比较版本
  -> 接受或拒绝修改
```

产品最终必须帮助用户回答：

1. 哪些用例失败？
2. 失败发生在工具选择、参数、回答还是权限？
3. 新版修复了什么，又破坏了什么？
4. 是否出现不能接受的安全硬失败？

## 4. MVP 功能

### 4.1 必须有

- JSONL 用例导入与校验；
- Reference Agent 和一个真实模型适配器；
- 回答、工具轨迹、参数、耗时、Token 和错误记录；
- 工具、参数、文本、拒绝、限制和安全规则评测；
- 至少 30 条正式用例；
- baseline/candidate 版本比较；
- JSON 和静态 HTML 报告；
- Fake Tool 安全测试；
- 可复现命令和匿名结果。

### 4.2 可选

- 重复运行与稳定性统计；
- LLM-as-a-judge；
- SQLite 历史记录；
- FastAPI 本地服务；
- 页面搜索、筛选和导出；
- 3 人可用性测试。

### 4.3 不做

- Agent 搭建与拖拽工作流；
- 多智能体协作平台；
- 自动修复所有问题；
- 大规模模型排行榜；
- 云端账号、团队、权限和计费；
- 对真实第三方系统执行危险安全测试。

## 5. 结果页面必须展示什么

### 单次运行

- 总用例数和通过率；
- 安全硬失败数；
- 平均耗时和 P95 耗时；
- Token 汇总；
- 每条用例的输入、输出、工具调用、参数和失败原因。

### 版本比较

- `improvement`：旧版失败，新版通过；
- `regression`：旧版通过，新版失败；
- `unchanged_pass`：两版都通过；
- `unchanged_failure`：两版都失败；
- 新增安全硬失败；
- 延迟和 Token 的变化。

不使用一个综合总分掩盖越权或泄漏问题。

## 6. 成功标准

### 工程成功

- 一条命令运行测试；
- 一条命令运行评测；
- 至少一个真实模型 Agent 可接入；
- 30 条以上正式用例，其中安全用例不少于 10 条；
- 可以比较两个版本；
- JSON 和 HTML 报告可重新生成；
- 异常不会导致整批结果丢失；
- 报告不包含真实密钥或私人数据。

### 作品集成功

- 展示一个真实失败和修复过程；
- Demo 能讲清“发现—定位—修改—回归比较”；
- 所有简历数字都能在报告中找到；
- 公开材料明确区分 Mock、smoke、screening 和 formal 结果。

### AI 产品岗位的额外证据

如果时间允许，邀请 3 名做过 Agent、RAG 或课程项目的同学完成“导入—运行—找失败—比较版本”的任务测试，记录完成时间、卡点和实际行为。该项不是 AI Agent 岗位的完成门槛。

## 7. 风险与取舍

| 风险 | 应对方式 |
|---|---|
| 两周内功能过多 | 静态 HTML 替代 FastAPI + SQLite + 复杂前端 |
| 真实模型成本失控 | 开发阶段用 Fake/Reference，冻结后再做正式运行 |
| 安全测试产生真实副作用 | 只使用 Fake Sink 和测试 Canary |
| Agent 太弱导致“看似安全” | 正常任务能力和安全指标分开报告 |
| 只展示成功样例 | 保存所有失败、取消和未运行项 |
| AI 写出的项目代码有风险 | 执行独立的 AI 辅助开发安全检查 |

## 8. 当前状态与下一步

当前完成的是离线 `smoke_only` 闭环。下一步是扩展用例字段、增加数据集级校验和统一失败代码。详细顺序以 [开发文档](DEVELOPMENT_SPEC.md) 为准。
